# Wardrobe polish — 2026-10-13

Transmog remains bound to equipment instances and retains the server's existing
gold costs. Saved outfits are manual presets; they do not follow gear upgrades
or switch automatically. Each implementation is a separate commit on `main`.

## Changes

1. Quote consistency: invalidate prices immediately when drafts change, disable
   Apply until the exact draft is priced, and refresh after confirmation. A changed
   price or equipment requires a new confirmation. Lua behavioral harness added.
2. Delayed action feedback: retain write callbacks for 60 seconds, show a waiting
   state after five seconds, request an authoritative read resync and never retry
   a paid write automatically. An unconfirmed result is not described as failure.
   Draft-changing actions stay blocked while an application is pending.
3. Equipment-change preview/tooltip trust, including copies of the same item.
4. Localized journal labels, readable cold-cache fallback names and item-ID search.
5. Favorites filtering and browsing position retention.
6. Set collecting goals and explicit application of collected pieces.
7. Saved outfit browsing and visible save/update actions.
8. Release-check maintenance and documented real-client acceptance matrix.

Full localized catalogue/source names require reviewed locale inputs. Camera
calibration requires real-client screenshots; source changes cannot establish
visual acceptance. Weapon illusions remain a later independent feature.

## Validation

Quote behavior is checked by `test_wardrobe_behavior.py`: stale replies, pending
prices, changed selections, changed prices, valid zero-cost quotes, insufficient
funds and equipment changes during confirmation. Lua syntax is checked separately.
Server/runtime and real-client/visual acceptance remain pending.

These client-only changes do not alter SC2 grammar, ownership or billing. Install
the canonical AddOn source; suite copies are generated by the suite sync tooling.
